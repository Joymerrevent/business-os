# /approve

## 何をするか

承認待ちの提案を 1 件ずつ人間に示し、承認されたものだけを反映する。人間の判断は 2 回。

1. この Skill の中で「承認」と答える
2. 反映の瞬間に Claude Code が出す権限の確認に「はい」と答える

提案の `status` を変えるのはこの Skill だけ。この Skill はサブエージェントに任せず、本文脈で動かす
（承認の質問はサブエージェントの中からはできない）。

```text
proposed → approving → approved
         → rejected
```

## 何を読むか

1. `${CLAUDE_SKILL_DIR}/../../templates/skill-conventions.md`（共通規約。最初に必ず読む）
2. `docs/proposals/` の全ての提案のうち、`status` が `proposed` か `approving` のもの
3. 各提案の `target` の現在の内容

## 手順

### 1. 一覧

承認待ちの提案を、古い順に一覧で示す（id、題、target、作成日）。

- `approving` のまま残っているものがあれば先に示す。前回の反映が途中で止まったもので、提案ごとに質問 1 を聞く
- 承認待ちが無ければ「承認待ちの提案はありません」と告げて終える

### 2. 1 件ずつ確認

各提案について次を示す。

- 背景、変更内容、差分（`target` の現在の内容と、変更後の内容）
- 根拠の鮮度：参照した文書の `as_of` / `updated`。共通規約の期限より古いものは「N 日前の情報です」と明示する
- `target` が提案の差分を書いた時点から変わっていれば、そのことを告げる（差分が古い）

そのうえで質問 2 を聞く。

### 3. 承認されたら

1. 提案の `status` を `approving`、`updated` を今日にする
2. `target` を変更する。憲章なら `updated` と `verified`（人間が確かめた日）を今日にする。
   ここで Claude Code が権限の確認を出すので、人間が「はい」と答える
3. 反映できたら、提案の `status` を `approved` にする
4. 権限の確認で「いいえ」と答えられた、または書き込みが拒否されたら、提案を `proposed` に戻し、その理由を提案の末尾に追記する

### 4. 却下されたら

提案の `status` を `rejected` にし、質問 3 を聞いて、答えを提案の末尾に「## 却下の理由」として追記する。

### 5. 修正を求められたら

質問 4 を聞き、提案の本文（変更内容と差分）を書き直す。`status` は `proposed` のまま。
書き直した提案をもう一度示して、2. からやり直す。

## 何を書くか

- 提案ファイルの `status` と `updated`、却下・差し戻しの理由
- 承認された提案の `target`（憲章、地図、安全設定、business-os の状態）
- 日報への実行記録（例：`- 09:10 /approve — 承認 2 件、却下 1 件`）

## 人に何を聞くか

表の番号の順に聞く。聞き方は共通規約の「人への質問」に従う。

| 番号 | 見出し | 質問文 | 答えの形 | 選択肢 | 聞くとき |
|---|---|---|---|---|---|
| 1 | 反映の途中 | 前回の反映が途中で止まった提案です。もう一度反映しますか、proposed に戻しますか。 | 選択肢（単一） | もう一度反映する / proposed に戻す | `approving` の提案があるとき（提案ごと） |
| 2 | 提案の判断 | この提案をどうしますか。 | 選択肢（単一） | 承認 / 却下 / 修正 / 保留（今回は判断しない） | 提案ごと |
| 3 | 却下の理由 | 却下の理由を教えてください。 | 自由記述 | — | 質問 2 で「却下」を選んだとき |
| 4 | 修正の内容 | どう直しますか。直したい点を教えてください。 | 自由記述 | — | 質問 2 で「修正」を選んだとき |
| 5 | コミット | 書いたファイルをコミットしてよいですか。 | 選択肢（単一） | コミットする / しない | 最後（ファイルを書いたとき） |

反映の瞬間の権限の確認は、Claude Code が出す。表には無い。

## 完了条件

- この回で扱った提案が `approved`、`rejected`、`proposed`（修正・保留・差し戻し）のどれかになっている
- `approving` のまま残った提案が無い
- 承認された変更が `target` に反映され、憲章なら `verified` が今日になっている
- 日報に実行記録が 1 行ある
