# 受け入れはマイルストーンの無い Issue にも走らせ、`from-review` の Issue だけマイルストーンが付くまで待つ

[要件定義書][req]の D-15 を決める。I12 の対象の条件とマイルストーンの候補の矛盾を解く。

## 背景と課題（Context and Problem Statement）

I12 は受け入れの対象を「`agent-ready` も受け入れの印も無く、マイルストーンがある Issue」とし、同時に「マイルストーンの候補（open な 0.x のうち版が最小のもの。人が先に付けていればそれ）」を下書きに書くとする。対象をマイルストーンのある Issue に限れば候補は常に「人が先に付けた値」になり、候補を出す意味が無い。
「マイルストーンがある」の条件は、R4-1b で 🟢 から起票する `from-review` の Issue が毎日増えて人の読む量を超えないために、「人がマイルストーンを付けるまで受け入れを走らせない」とした判断から来ている。外の人やコラボレータが立てた普通の Issue まで止める意図ではなかった。

## 判断の決め手（Decision Drivers）

- 普通の Issue は起票の翌日に下書きが付き、人が 1 操作で処理対象にできる（2 節の人の関所）
- `from-review` の Issue が人の読む量を超えない（R4-1b）
- 受け入れの件数の上限（I12）で利用枠を押さえる

## 検討した選択肢（Considered Options）

問い：受け入れをどの Issue に走らせるか。マイルストーンの候補を出すか。

- 案A：**`from-review` だけマイルストーンを待ち、他は走らせて候補を出す**。対象は「`agent-ready` も受け入れの印も無い Issue」。`from-review` のラベルがある Issue だけ「マイルストーンがあること」を条件に足す
- 案B：**マイルストーンのある Issue だけ走らせ、候補は出さない**。今の I12 の対象の条件のまま、候補をやめる
- 案C：**すべて走らせる**。対象を限らず、`from-review` も毎回受け入れる

## 決定（Decision Outcome）

採用した選択肢:「案A：`from-review` だけマイルストーンを待ち、他は走らせて候補を出す」。理由: R4-1b の目的（🟢 の Issue の洪水を防ぐ）を `from-review` だけに限って保ち、普通の Issue の受け入れを止めない。

中身：

- 受け入れの対象：Project にあり、`agent-ready` が無く、受け入れの印（`intake`）が無く、`needs-human` が無い Issue。ただし `from-review` のラベルがある Issue は、マイルストーンが付いているときだけ対象
- マイルストーンの候補：人が先に付けていればそれ。無ければ open なマイルストーンのうち版が最小のもの（`0.x` に限らない。版の比較は semver の順）。候補は下書きに書き、`agent-ready` の後に進行役が確定して付ける（4.10 節の 2c）
- 候補の対象になるマイルストーンが無ければ、下書きに「マイルストーン：無し。人が付ける」と書き、`agent-ready` の後も付けない。棚卸し（R1-1）はマイルストーンの無い Issue を候補にしないので、人が付けるまで着手しない
- 受け入れの件数の上限（I12、8 節）はそのまま

### 影響（Consequences）

- 良い点: 普通の Issue は起票の翌日に下書きが付く
- 良い点: `from-review` の Issue は人がマイルストーンで選別してから受け入れが走る
- 悪い点: 外の人が Issue を大量に立てると受け入れ AI が走る。件数の上限と `needs-human`（検疫）で押さえる

### 確認方法（Confirmation）

- 結合テストで、マイルストーンの無い普通の Issue に下書きが付き、`from-review` の Issue には付かないことを検査する

## 選択肢ごとの長所と短所（Pros and Cons of the Options）

### 案A：`from-review` だけマイルストーンを待つ

- 良い点: R4-1b の意図どおり
- 悪い点: 条件が 1 つ増える

### 案B：マイルストーンのある Issue だけ

- 悪い点: 普通の Issue も人がマイルストーンを付けるまで下書きが付かず、「人の操作は `agent-ready` の 1 つ」（2 節）が 2 つになる
- 却下

### 案C：限らない

- 悪い点: 🟢 の Issue が毎日受け入れを走らせ、人の読む量を超える
- 却下
