# CI の結果ごとの扱いと、1 回の実行で 2 件目以降の PR のマージ判定を次回に回すこと

[要件定義書][req]の D-3 と D-4 を決める。R4-3 と R7-3b を補う。

## 背景と課題（Context and Problem Statement）

R4-3 は収束の条件を「CI が緑、かつ最新のラウンドの印が pass」とし、緑でないときの扱いを「緑ではない」としか書いていない。レビューが pass なのに CI が赤のとき、何もしなければその PR は永久に収束しない。
CI の結論には「赤（failure）」のほかに「まだ無い（push 直後）」「保留（pending）」「取り消し（concurrency による cancelled）」があり、どれを修正に回すかで、利用枠と往復の回数が変わる。
また R7-3b は「1 回の実行で `merge=ready` にするのは 1 件まで」とするが、2 件目の PR に何を書くかを決めていない。基本設計は `merge=human` としたが、人がそれをマージすると R7-2b の数え方で「不一致」になり、段階 5 の出口の記録を汚す。

## 判断の決め手（Decision Drivers）

- 検査が走っていない変更を通さない（R4-3）
- CI の遅れだけで修正のセッションを起こさない（利用枠と往復の節約）
- 段階 5 の一致の記録を、判定と無関係な事情で汚さない

## 検討した選択肢（Considered Options）

1. 赤だけを修正に回し往復に数える。無い・保留・取り消しは待つ。2 件目のマージ判定は次回に回し印を書かない
2. 緑でないものをすべて修正に回す
3. 2 件目を `merge=human` にする（基本設計の案）

## 決定（Decision Outcome）

採用した選択肢:「1」。理由: 赤は作業の結果なので作業 AI に直させるのが筋で、無い・保留・取り消しは時間が解決するか再実行で解決する。2 件目は判定を遅らせるだけで、判定の中身を変えない。

中身：

- CI の結論の扱い（必須チェックごと。1 つでも当たれば行の順で判定）

  | 結論 | 扱い |
  | --- | --- |
  | `failure`（赤）、`timed_out`、`action_required` | 修正へ。CI の失敗（チェック名と結論。ログは渡さない）をそのラウンドの 🔴 の指摘として作業 AI に渡し、往復に数える。`fix` の印の `round` は最新の `review` の印の `round` と同じ |
  | 無い（push 後にまだ作られていない）、`pending`、`queued`、`in_progress` | 待つ。次回の実行で読み直す。催促も修正もしない |
  | `cancelled`、`skipped`、`neutral`、`stale` | 待つ。同じ head で 2 回の実行で変わらなければ、人が再実行する前提で `needs-human` |
  | `success`（全部） | 緑 |

- 同じ名前のチェックが同じ head に複数あるとき（再実行）は、最新の 1 件を採る
- マージの判定（R7-2）の時点で CI が緑でなければ、判定を次回に回し `merge` の印を書かない（`human` にしない）
- 1 回の実行で `merge=ready` にできるのは 1 件まで。2 件目以降の PR は判定を次回に回し、印を書かない。どの PR を先にするかは PR 番号の昇順

### 影響（Consequences）

- 良い点: 修正のセッションは「作業の結果が赤」のときだけ起きる
- 良い点: `merge=human` は「満たさない条件がある」ときだけになり、一致の記録が汚れない
- 悪い点: CI の赤を 🔴 として渡すので、往復 3 回の上限を CI の失敗だけで使い切ることがある。それは `needs-human` でよい（壊れた変更を回し続けない）
- 悪い点: 2 件目以降は 1 日ずつ遅れる。WIP 1 の間は起きない

### 確認方法（Confirmation）

- 判定の表（基本設計 judgments）に本 ADR の表を写し、vitest で結論ごとの分岐を検査する

## 選択肢ごとの長所と短所（Pros and Cons of the Options）

### 1. 赤だけ修正、他は待つ、2 件目は次回

- 良い点: 利用枠と往復を無駄にしない
- 悪い点: 待ちの状態が増える（記録に理由を残す）

### 2. 緑でないものをすべて修正

- 悪い点: push 直後の「無い」でも修正のセッションが起きる。中身の無い修正で往復を消費する
- 却下

### 3. 2 件目を `merge=human`

- 悪い点: 人がマージすると不一致に数えられ、段階 5 の出口が判定と無関係に遠のく
- 却下
