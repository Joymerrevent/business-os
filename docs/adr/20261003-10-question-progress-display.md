# 20261003-10: 質問の先頭には、その回で何問目か・聞く見込みの数・表の番号を付ける

## 背景と問い

20261003-08 は、Skill が人に聞く質問を SKILL.md の質問の表で固定し、質問の先頭に「質問 <番号>/<総数>：<見出し>」を付けると決めた。
共通規約（`templates/skill-conventions.md`）は、<番号> を表の番号、<総数> を表の行数とし、条件に当たらない質問は飛ばして番号を詰めないと定めている。

2026-10-03 に利用者が `/onboard` の初回の導入を試し、「質問が 5/21 から始まった。なぜ 1/21 ではないのか」と指摘した。

- `/onboard` の表の 1〜4 は、条件があるときだけ聞く質問である（導入済みのとき、作業フォルダが git リポジトリでないとき、sandbox が使えないとき）。
  条件に当たらない初回の導入では、最初の質問が 5 番になる
- 分母の 21 は表の行数で、その回に聞く数ではない。初回の導入で聞くのは、事業ごとのくり返しを除いて 16 問前後である
- 20261003-08 は良い影響に「あと何問あるかも分かる」を挙げ、0.2.0 の CHANGELOG も同じことを書いた。表の行数を分母にする規約では、その効果は成り立っていない

一方、表の番号は 2 つの役目を持つ。利用者が同じ Skill で同じ質問を同じ番号で受けることと、質問の流れの進行役（`evals/lib/dialogue/steps.ts`）が応答の番号で台本の項目を見分けることである。

問い：質問の先頭に付ける番号を、利用者にとって自然な進み具合にしつつ、表の番号による照合を保てるか。

## 判断の基準

- 利用者が、最初の質問を 1 問目として受け、あと何問あるかの見当が付くこと
- 進行役が、言い回しに左右されずに質問を表の番号で見分けられること（20261003-08 の狙いを保つ）
- 同じ質問が、どの回でも同じ表の番号で示されること
- 書き換える範囲が小さいこと

## 検討した案

- 案 A：その回で何問目か・聞く見込みの数を見せ、表の番号を括弧で添える（例：「質問 1/16：会社の呼び名（表 5）」）
- 案 B：表の並びを入れ替え、毎回聞く質問を 1 番から並べ、条件付きの質問を後ろへ回す。表示の形は今のまま
- 案 C：分母をやめ、表の番号だけを見せる（例：「質問 5：会社の呼び名」）

## 決定

採用：**案 A**。利用者には 1 から始まる進み具合を見せ、進行役は括弧の中の表の番号で照合を続けられる。
案 B は、`/onboard` の git と sandbox の確認のように条件付きの質問を手順の先頭で聞く Skill で、番号が後ろから前へ戻る。
案 C は、5 から始まる違和感が残る。

20261003-08 の決定 2 のうち、質問の先頭に付ける形と聞き返しの付け方だけを置き換える。20261003-08 のほかの決定（質問の表の列、質問文をそのまま使うこと、1 ターンに 1 問、検査、進行役が番号で見分けること）は変えない。

1. 質問の先頭に「質問 <何問目>/<見込みの数>：<見出し>（表 <表の番号>）」を付ける
   - <何問目>：その回で聞いた質問の数に 1 を足した数。事業ごとのくり返しも 1 問と数える。聞き返しは数えない
   - <見込みの数>：その回で聞く見込みの質問の数。最初の質問の時点で、「聞くとき」の条件に当たる質問を数える。
     事業ごとにくり返す質問は、事業の数が分かっていれば事業の数だけ数え、分からなければ 1 問と数える
   - 事業の数が分かったときや、条件に当たる質問が増減したときは、次の質問から <見込みの数> を直す
   - 事業ごとなど同じ質問をくり返すときは、括弧に対象を添える（例：事業が 2 件の初回の導入で「質問 11/19：追いかける数字（事業 A、表 15）」）
2. 聞き返すときは「（表 <表の番号> の確認）」を付ける
3. 表の番号の振り方（1 からの連番、条件に当たらない質問は飛ばす）は 20261003-08 のまま変えない
4. 進行役は、応答の中の「表 <番号>」で台本の項目を見分ける。<何問目> と <見込みの数> は照合に使わない

## 影響

- 良い影響
  - 利用者は、最初の質問を 1 問目として受け、あと何問あるかの見当が付く
  - 表の番号は括弧に残るので、同じ質問はどの回でも同じ番号で示され、進行役の照合も続けられる
- 悪い影響
  - <見込みの数> は途中で増えることがある（`/onboard` で事業の数が分かったとき、Obsidian の導入の質問が加わったときなど）
  - CC が質問のたびに数を数えるので、数え違いが起こりうる。数え違いは表の番号による照合に影響しない
  - 表示が少し長くなる
- その他
  - 実装 PR で、共通規約（`templates/skill-conventions.md`）、進行役（`evals/lib/dialogue/steps.ts`）とそのテスト（`test/evals/dialogue-steps.test.ts`）を直す。
    質問の表を持つ SKILL.md 10 件と台本 3 件は、表の番号と見出しが変わらないので直さない
  - 実装 PR では、全ての台本を流し直し、結果が変わらないことを確かめる。利用者に届く変更なので changeset を書く

## 案ごとの長所と短所

### 案 A：何問目と見込みの数を見せ、表の番号を添える

- 長所：利用者には 1 から始まる進み具合が見え、照合用の番号も残る。表と台本を直さなくてよい
- 短所：表示が長くなる。<見込みの数> が途中で増えることがある

### 案 B：表の並びを入れ替える

- 長所：表示の形を変えない
- 短所：条件付きの質問を手順の先頭で聞く Skill では、番号が後ろから前へ戻る。表・台本・eval の回答表の番号を全て振り直す。分母が表の行数である問題は残る

### 案 C：分母をやめる

- 長所：変更がいちばん小さい
- 短所：5 から始まる違和感が残る。あと何問あるかが分からない
