# 20261003-06: 新しい ADR は MADR 形式で書き、既存の ADR は書き直さない

## 背景と問い

2026-10-03 時点で、business-os の ADR は 17 本あり、本文はすべて `docs/adr/README.md` の「本文の構成」に従っている。
構成は 背景・決定・根拠・影響・参考 の 5 節で、他の選択肢は「根拠」の節の中に「検討した代替案」として書いている（17 本中 16 本）。

5 節の構成では、採った案を「決定」に先に書き、捨てた案を後から「根拠」で挙げる。次の 2 つが本文に残らない。

- 何を重視して選んだか（判断の基準）
- 採った案の短所と、捨てた案の長所

判断の基準が残らないと、前提が変わったときに、どの決定を見直すべきかを本文から判断できない。
採った案の短所が残らないと、決定に後付けで理由を足したのか、比べた上で選んだのかを読み手が区別できない。

ADR の形式は README の運用ルールでだけ決めていて、形式を決めた ADR は無い。
新しい ADR の本文をどの形式で書くか、既存の 17 本をどう扱うかを決める。

## 判断の基準

- 判断の基準と、採った案の短所が本文に残ること
- 起票する人（CC を含む）が、雛形を埋めるだけで比較の形になること
- accepted の ADR を書き換えないこと（README の status の遷移）
- 小さな判断でも、書く量が負担になりすぎないこと
- フロントマターの規則（4 日付欄、`check:docs` と `check:adr` の検査）を変えずに済むこと

## 検討した案

- 案 A：新しい ADR を MADR 形式で書き、既存の ADR は書き直さない
- 案 B：今の 5 節を保ち、雛形の「根拠」に「検討した代替案」の見出しを置くだけにする
- 案 C：MADR 形式に切り替え、既存の 17 本も書き直す
- 案 D：MADR 形式から「案ごとの長所と短所」の節を除いた軽い形にする

## 決定

採用：**案 A**。判断の基準と採った案の短所が残り、accepted の ADR を書き換えずに済むため。

1. この ADR 以降の新しい ADR は、本文を次の節で書く。MADR（Markdown Architectural Decision Records）の構成を、見出しを日本語にして使う
   1. **背景と問い**：何が問題で、なぜ今決めるのか。解く問いを書く
   2. **判断の基準**：選ぶときに重視すること（制約・品質の要求）
   3. **検討した案**：案を一言ずつ並べる。採る案も捨てる案も同列に書く
   4. **決定**：採った案と、判断の基準に照らした理由。決定が複数あるときは番号を振る
   5. **影響**：良い影響・悪い影響・その他（新しく生まれる前提や制約）に分けて書く
   6. **案ごとの長所と短所**：「検討した案」の各案について、長所と短所を書く
   7. **参考**：出典、関連 ADR、外部リンク
2. フロントマターは変えない。欄・値の規則と検査は今のまま
3. 既存の ADR（20260929-01 〜 20261003-05）は書き直さない。5 節の構成のまま残す。2 つの形式が `docs/adr/` に並ぶ
4. 節の構成は `docs/adr/_template.md`（雛形）を正本とし、`docs/adr/README.md` は雛形を指す。README には、どの id から形式が変わったかを書く
5. 節の有無は機械で検査しない

## 影響

- 良い影響
  - 判断の基準が残るので、前提が変わったときに見直す ADR を探しやすくなる
  - 採った案の短所も書くので、決定が抱える負債が本文から分かる
- 悪い影響
  - 1 本あたりの書く量が増える。特に「案ごとの長所と短所」は、案の数に比例して長くなる
  - `docs/adr/` に 2 つの形式が並ぶ。古い ADR を読むときは、5 節の構成で読む必要がある。前提が変わった ADR は MADR 形式の新しい ADR で置き換えるので、有効な判断ほど新しい形式に移り、混在は時間とともに小さくなる
- その他
  - 実装として、雛形 `docs/adr/_template.md` と `docs/adr/README.md` の「本文の構成」を MADR 形式に直す。この ADR が accepted になってから、別の PR で行う
  - 節の有無を検査しないため、節が欠けても `pnpm check` は通る。欠けた節はレビューで見つける
  - 次のどれかが起きたら、節の検査を足すかを見直す：節の欠けた ADR が accepted になった、起票する人が雛形を使わずに書く場面がくり返し起きた

## 案ごとの長所と短所

### 案 A：新しい ADR を MADR 形式で書き、既存の ADR は書き直さない

- 長所：判断の基準と、全案の長所・短所が残る
- 長所：accepted の ADR を書き換えない
- 短所：2 つの形式が並ぶ
- 短所：1 本あたりの書く量が増える

### 案 B：今の 5 節を保ち、雛形に「検討した代替案」の見出しを置くだけにする

- 長所：変更が最も小さい。形式が 1 つのまま
- 短所：判断の基準と、採った案の短所が残らない。背景で挙げた問題が解けない

### 案 C：MADR 形式に切り替え、既存の 17 本も書き直す

- 長所：形式が 1 つにそろう
- 長所：将来、節を機械で検査するときに例外が要らない（案 A でも「20261003-06 以降を検査する」と書けば済むので、差は小さい）
- 長所：既存の 17 本は 2026-09-29 〜 2026-10-03 に書かれ、決めた本人の記憶が新しい。書き直す費用は今がいちばん小さい
- 短所：accepted の ADR を書き換えることになり、README の status の遷移の規則に反する
- 短所：既存の ADR には判断の基準が書かれていないので、書き直すと決めた当時に無かった理由を後から足すことになる。後から整えた理由と当時の理由を本文で区別できなくなる
- 短所：17 本すべてをメンテナが読み直して確認する必要がある。書き直しで意味がずれても `pnpm check` では見つからない

### 案 D：MADR 形式から「案ごとの長所と短所」の節を除く

- 長所：案 A より書く量が少ない
- 短所：採った案の短所が残らず、案 B と同じ問題が半分残る
