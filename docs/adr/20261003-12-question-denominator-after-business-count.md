# 20261003-12: 事業ごとにくり返す質問がある Skill では、事業の数が分かるまで質問の数の見込みを出さない

## 背景と問い

20261003-10 は、質問の先頭に「質問 <何問目>/<見込みの数>：<見出し>（質問 ID：<表の番号>）」を付けると決めた。
事業ごとにくり返す質問は、事業の数が分からなければ 1 問と数え、事業の数が分かったら次の質問から見込みの数を直す。

2026-10-03 に、20261003-10 の実装（#51）で `/onboard` の初回の導入の台本を流した。事業が 2 件の回で、見込みの数は 16 → 19 → 18 と変わった。

- 16 → 19：事業の一覧（質問 ID：9）で事業が 2 件と分かり、事業ごとの質問 3 問が 1 事業分から 2 事業分になった
- 19 → 18：事業 B の実装リポジトリを、事業 A への答えで済ませた

メンテナは、見込みの数が途中で増えるのを避けたいと判断した。いちばん大きく動くのは事業の数が分かったときで、`/onboard` では 5 問目の前後にあたる。

問い：事業の数が分かるまでの見込みの数を、どう見せるか。

## 判断の基準

- 利用者に見せた質問の数が、後から大きく増えないこと
- 質問 ID による照合（20261003-08、20261003-10）を保つこと
- 事業ごとにくり返す質問を持たない Skill の表示を変えないこと

## 検討した案

- 案 A：事業の数が分かるまでは見込みの数を出さず、「質問 <何問目>：<見出し>（質問 ID：<表の番号>）」と表示する
- 案 B：事業の一覧を最初の質問にして、早く事業の数を確定させる
- 案 C：今のまま、1 事業分で数えて、事業の数が分かったら直す（20261003-10 のまま）

## 決定

採用：**案 A**。メンテナが 2026-10-03 に会話の中で選んだ。
見込みの数がいちばん大きく増える場面をなくし、質問 ID と何問目の表示はそのまま保てる。
案 B は質問の表の並びと番号を振り直すことになり、`/onboard` の会社の質問から事業の質問へ進む流れも崩れる。

20261003-10 の決定 1 のうち、<見込みの数> の扱いだけを置き換える。20261003-10 のほかの決定（何問目の数え方、質問 ID の見せ方、聞き返しの付け方、進行役が質問 ID で見分けること）は変えない。

1. 事業ごとにくり返す質問が表にあり、その回の事業の数がまだ分からないときは、<見込みの数> を出さない
   - 表示は「質問 <何問目>：<見出し>（質問 ID：<表の番号>）」（例：「質問 1：会社の呼び名（質問 ID：5）」）
   - 事業の数が分かった次の質問から、「質問 <何問目>/<見込みの数>」の形にする
2. 事業ごとにくり返す質問を持たない Skill と、事業の数が始めから分かっている回（`/onboard` で事業を追加するときなど）は、最初の質問から <見込みの数> を出す
3. 事業の数が分かった後に、質問が要らなくなったときや増えたときに <見込みの数> を直す決まりは、20261003-10 のまま変えない
4. 進行役は、<見込みの数> の有無にかかわらず、質問の先頭の行の質問 ID で見分ける

## 影響

- 良い影響
  - 事業の数による見込みの数の増加（`/onboard` で 16 → 19 など）が、利用者に見えなくなる
  - 事業ごとの質問を持たない Skill は、表示が変わらない
- 悪い影響
  - `/onboard` の最初の数問は、あと何問あるかが分からない
  - 済んだ質問の飛ばしや、条件付きの質問の追加（Obsidian の導入など）による見込みの数の変化は残る
- その他
  - 実装は #51 に積む。共通規約（`templates/skill-conventions.md`）、進行役（`evals/lib/dialogue/steps.ts`）とそのテストを直す

## 案ごとの長所と短所

### 案 A：事業の数が分かるまで見込みの数を出さない

- 長所：見込みの数がいちばん大きく増える場面がなくなる。質問の表と台本を変えない
- 短所：最初の数問は、あと何問あるかが分からない

### 案 B：事業の一覧を最初に聞く

- 長所：最初の質問のすぐ後から見込みの数を出せる
- 短所：質問の表の並びと番号、台本、eval の回答表を振り直す。会社の質問の途中に事業の質問が入る

### 案 C：今のまま

- 長所：変更が無い
- 短所：事業の数が分かったときに、見込みの数が大きく増える
