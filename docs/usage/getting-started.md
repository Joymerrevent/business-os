# はじめる

business-os は、1 人で複数の事業を運営する人が Claude Code（CC）を「経営の手足」として使うための器です。
CC の Plugin として配布されています。この文書は、導入から最初の 1 週間までを案内します。

> **Status: Alpha (0.x)** — 仕様は変わります。本番の経営判断に使う場合は自己責任でお願いします。

## 何ができるか

- 毎朝、今日の優先事項・承認待ち・期限を 1 枚にまとめる
- 週・月・四半期の周期で、実績の確認と方向の見直しを促す
- 意思決定を記録し、後から「なぜそう決めたか」を辿れる
- CC が会社の方針を勝手に書き換えないよう、承認の仕組みで守る
- 使っているうちに、繰り返す作業を CC が見つけて Skill 化を提案する

business-os は「何をやるべきか」を決めてくれません。決めるのはあなたです。
決めるための材料を毎日・毎週揃え、決めたことを記録し、忘れないようにするのが器の仕事です。

## 前提

| 必要なもの | 備考 |
|---|---|
| Claude Code | Plugin に対応した版 |
| Node.js 24 系 | hook と検査の実行に使います |
| Git、GitHub アカウント | 事業データを自分のリポジトリで管理します |
| macOS または Windows | Windows は WSL を推奨します（下の「Windows で使う場合」を参照） |
| Obsidian | 任意。使うと便利ですが、無くても全機能が動きます |

会社経営の知識は要りません。器が聞くことに答えていけば形になります。

## 導入（3 ステップ）

### 1. Plugin を入れる

CC を起動して、次の 2 行を実行します。

```text
/plugin marketplace add Joymerrevent/business-os
/plugin install business-os@business-os
```

### 2. 事業データ用のリポジトリを作る

器とは別に、あなたの事業データを置く**非公開**リポジトリを作ります。名前は何でも構いません
（この文書では `company` と呼びます）。

```bash
mkdir company && cd company && git init
```

### 3. `/onboard` を実行する

`company` の中で CC を起動し、`/onboard` と入力します。CC があなたの会社についてインタビューし、
答えから必要なファイルを生成します。手で Markdown を書く必要はありません。

聞かれること：

- 会社の呼び名、一行説明、目指すこと、優先順位
- 運営している事業の一覧（名前と一言説明）
- CC に任せてよい範囲と、あなたの承認が要る範囲
- 忘れてはいけない期限や義務（申告、支払い、契約更新）
- 各事業の実装リポジトリの場所（あれば）
- 各事業で追いかける数字（候補から選ぶ形です）
- ナレッジの閲覧に Obsidian を使うか

答えに迷う項目は「まだ決めていない」で構いません。後から `/onboard` を再実行して埋められます。

終わると、`company` の中に次のものができています。

```text
company/
├── CLAUDE.md          CC が毎回読む地図
├── .claude/           CC の安全設定
└── docs/
    ├── charter/       憲章：会社の定義と判断ルール。あなたが管理し、CC は提案だけ
    ├── proposals/     CC からの提案。あなたが承認すると憲章に反映される
    ├── decisions/     意思決定の記録
    ├── operations/    台帳・日報・レビュー。CC が書く
    ├── knowledge/     調査やメモ。CC が書く
    ├── inbox/         あなたが自由にメモを放り込む場所
    └── archive/
```

## 最初の 1 週間

### Day 1

`/morning` を実行します。運営初日なので「データ不足」が多く出ますが正常です。
今日やることを 3 つ決めて、あとは普段の仕事に戻ってください。

### Day 2〜7

毎朝 `claude` を開いて `/morning`。それだけです。
日中、CC に何か頼んだら、その記録は自動で日報に残ります。

### 週末

- `/weekly-review`：今週の実績と来週の重点を確認します
- `/check`：器の安全装置が正しく動いているかを点検します。初回は必ず実行してください

### 最初の月末

`/close` で月次の締めをします。数字を聞かれるので、手元の売上・費用・残高を用意してください。
正確でなくて構いません。「いつ時点の数字か」だけは正確に答えてください。

## Obsidian を使う場合（任意）

`/onboard` で「使う」と答えると、CC が Obsidian の設定と、承認待ち・決定記録・事業別現況・鮮度の
ダッシュボード、メモと日報の雛形を用意します。Obsidian が未インストールなら、確認の上でインストールも行います。

`/onboard` が終わったら、Obsidian を起動し、最初の画面の「保管庫としてフォルダを開く」で `company/docs/` を選んでください。
`company/` そのものではありません。

- 新しいメモは `inbox/` にできます。テンプレートの挿入で `inbox-note` を入れると、必要な情報（フロントマター）が付きます
- 今日の日報は、Obsidian の「今日のデイリーノートを開く」でも開けます。`/morning` は同じファイルに書き込みます
- Windows でのインストール（winget）で管理者の確認が出るかは、この版ではまだ確かめていません

Windows で Obsidian を使う場合は、下の「Windows で使う場合」を先に読んでください。

## Windows で使う場合

Windows では、WSL（Windows 上で Linux を動かす仕組み）の中で CC を動かす構成を勧めます。
WSL では macOS と同じ手順で使え、安全装置もすべて働きます。ただし Obsidian は使いません。

Obsidian を使いたい場合は、WSL を使わずに Windows 上で直接 CC を動かし、`company` を Windows 側に置く
構成も選べます。WSL 上のファイルを Obsidian で開くと動作が不安定になるためです。
この構成では、CC のコマンドを OS が見張る仕組み（sandbox）が Windows で動きません。
憲章の保護は、器の見張り（hook）と CC の権限設定だけに頼ることになります。

`/onboard` は sandbox が使えない環境を見つけると、そのことを伝えてから、続けてよいかを確認します。

## 困ったとき

- 安全装置が動いているか不安 → `/check`
- 「先に提案を書け」と言われた → 憲章はあなたが管理する領域です。CC は `docs/proposals/` に提案を書くので、
  `/approve` で確認して反映してください
- 起動時に警告が出た → 表示された対処（多くは `/onboard` の再実行）に従ってください
- `/morning` などで別の Skill が動いた → 同じ名前の Skill をあなたが持っています。`/business-os:morning` のように
  `business-os:` を付けて呼んでください
- 不具合・提案 → 器のリポジトリの Issues へ。事業データは絶対に貼らないでください

## やめるとき

`/plugin uninstall business-os` で器は消えます。`company/` の中身は普通の Markdown なので、
そのまま残り、どのエディタでも読めます。Obsidian を使っていた場合は `company/docs/.obsidian/` を
消せば元に戻ります（`company/docs/dashboards/` と `company/docs/_templates/` も消して構いません）。
